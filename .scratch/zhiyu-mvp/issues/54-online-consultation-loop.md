# 54 — 在线问诊主闭环

**What to build:** 患者从独立“在线问诊”入口锁定健康档案，经 Agent 预问诊反复调整并确认病情摘要；问诊单进入平台级标准科室待接诊池，合格医生在 B 端明确接受后与患者进行轮询图文交流或模拟视频问诊，填写诊断与医嘱并完成问诊。C 端全程展示跨 C/B 端五步进度，在线问诊不创建挂号单、不占线下号源、不收问诊费。

**Blocked by:** 49 — AI挂号助手动态城市与确定性自助挂号；50 — 智能导诊标准科室与科室号源卡

**Status:** claimed

- [ ] C 端新增独立“在线问诊”入口；普通 Agent 会话中的症状描述不得静默进入预问诊或创建在线问诊单
- [ ] 进入预问诊时必须存在激活健康档案并锁定为本次服务对象；后续切换档案不得改变草稿或问诊单归属
- [ ] 预问诊草稿独立关联患者、锁定健康档案和会话；删除会话只解除关联，不删除草稿、在线问诊或临床业务记录
- [ ] server-java 校验草稿归属与状态后强制使用 preconsultation 场景，不信任客户端自由指定场景获得预问诊权限
- [ ] server-py 的 preconsultation 场景一次只追问一个关键问题，并持续更新含主诉、现病史、过敏史和免责声明标注的结构化病情摘要
- [ ] preconsultation 场景不得暴露医生推荐、号源查询、创建挂号或查询挂号工具；普通 triage 与 interpretation 场景行为保持不变
- [ ] 患者可继续与 Agent 对话补充或纠正信息，摘要随成功轮次形成新快照；摘要更新失败保留上一版本且不丢失对话
- [ ] 摘要页只负责展示、继续调整和明确确认，不嵌入医生选择；标准科室必须从平台目录受控解析并由 server-java 校验
- [ ] 患者确认摘要后幂等创建在线问诊单并进入 WAITING_DOCTOR；重复确认返回同一问诊单，不产生重复记录
- [ ] 每份健康档案最多存在一条 WAITING_DOCTOR 或 IN_PROGRESS 问诊；不同健康档案可分别发起
- [ ] C 端固定展示“AI 预问诊 → 患者确认摘要 → 等待医生接诊 → 医生问诊中 → 问诊已完成”五步进度，不展示预问诊内部字段百分比
- [ ] WAITING_DOCTOR 阶段患者可主动取消；创建后默认 10 分钟无人接受则惰性收敛为 EXPIRED，医生不可再接受
- [ ] CANCELLED 或 EXPIRED 问诊可复用原摘要重新提交，无需重复预问诊
- [ ] 科室待接诊池按标准科室在平台范围开放，不受城市、医院、院区、线下排班或号源限制
- [ ] 只有拥有 B 端医生账号且实际科室映射到相同标准科室的医生可查看问诊单摘要和接受问诊；其他医生不得读取患者详情
- [ ] 医生查看摘要不推进状态；只有明确接受才能从 WAITING_DOCTOR 进入 IN_PROGRESS 并绑定该医生
- [ ] 两名合格医生并发接受同一问诊单时恰好一人成功，doctor_id 与 accepted_at 只写一次，失败者得到明确冲突
- [ ] 医生接受后 C 端通过短轮询获得可信医生姓名、职称、医院和科室并进入“医生问诊中”
- [ ] 图文问诊使用独立持久化医患消息，C/B 端可双向发送并增量轮询；消息不得进入 Agent 会话、审计原文或 Agent trace
- [ ] 视频问诊只持久化方式与模拟开始状态，C 端展示医生身份、连接状态和计时；不得接入真实音视频、WebRTC 或媒体服务器
- [ ] 只有已绑定患者与医生可读写医患消息，且只在 IN_PROGRESS 允许发送；COMPLETED 后记录只读
- [ ] 医生填写诊断结论与医嘱后幂等完成问诊，状态推进为 COMPLETED；在线问诊不创建挂号收费记录
- [ ] 所有在线问诊状态、决定、进度、接诊方式、消息发送者类型、默认超时和文案均从 contracts 推导，Java/Python/TypeScript 无私写枚举
- [ ] 新实体、DTO 与 View 映射使用 MapStruct；业务逻辑进入既有分层，controller/路由不包含 SQL 或业务逻辑
- [ ] MockMvc 覆盖 C/B 端完整 HTTP 外部行为及归属、跨科室、非法状态、取消、失效、重复提交等负向路径
- [ ] PostgreSQL 集成测试覆盖医生原子接受、每档案单一进行中问诊和失效后不可接受，不以真实等待验证 10 分钟超时
- [ ] server-py 使用 TestClient 与 fake 覆盖一次一问、摘要快照、知识与工具隔离、受控标准科室解析和失败降级
- [ ] 支付宝开发者工具与浏览器人工走通“入口 → 锁定档案 → 预问诊 → 摘要确认 → 医生接受 → 图文/模拟视频 → 诊断医嘱 → 完成”，两端无红色控制台错误
- [ ] 完成前更新 Spec 0003 对应决策、CONTEXT.md 术语（如有变化）、票单 checklist，并在 README 依赖图将 54 节点标记为 `[x]54`

实施边界：本票不做在线问诊开方、处方审核或购药；这些由票 55 在本票稳定的在线问诊身份、状态和接诊记录之上完成。不得为了复用现有接诊台而创建虚假挂号单、可空排班或扣减线下号源。
