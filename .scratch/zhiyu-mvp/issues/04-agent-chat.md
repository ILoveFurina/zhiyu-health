# 04 — Agent 对话主干（含红线安全门、开场提示词与推理档位）

> **Superseded by:** 票 31 — ADR-0009 后本票拆为双栈形态：会话持久化/对话入口/红线规则迁 server-java，LangGraph 循环留 server-py。

**What to build:** 小程序聊天页与 Agent 多轮对话打通：LangGraph 循环接入 doubao-seed-2.1-turbo（ADR-0004/0005），会话与消息持久化；免责声明标注由后端统一注入并由全局组件渲染在每条 AI 健康建议上；Agent 主干内置红线症状确定性规则安全门，命中后立即中断导诊并展示红色警告与 120 提示；AI 页初始展示 3 个推荐提示词（导诊/用药注意/健康管理各一，点击即发）；用户可切换推理档位（自动/快速回答/深度思考，默认自动）；随此票建立 patients 表（仅承载 C 端 mock 登录身份）与免注册 mock 登录。

**Blocked by:** 01 — 项目骨架与基础设施

- [x] LangGraph Agent 循环支持多轮上下文（追问能力）

**实施备注（kimi/04-agent-chat 分支）：**

- 随 ADR-0008 直接落地支付宝小程序：微信骨架整体迁移（antd-mini + my.*），无微信残留。
- 支付宝 `my.request` 无分片回调，客户端完整读取 SSE 流后按事件序回放（打字机效果）；后端 SSE 契约不变，工具调用可视化同通道可用。
- 红线警告界定为规则引擎产物而非 AI 产出：SSE 事件、历史消息接口、红线卡 UI 三处一致不注入免责声明。
- B/C 端同名 auth 文件已拆分：B 端保留 `schemas/auth.py`/`services/auth.py`，C 端为 `schemas/c_auth.py`/`services/patient.py`；患者令牌带 `scope` 声明防两端混用。
- C 端测试随团队惯例用临时 SQLite 库；后续票接业务工具后需补"命中红线不调用工具"的断言。
