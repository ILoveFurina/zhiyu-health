# 53 — 药品查询回复采用半结构化 Markdown 排版

**What to build:** 优化 C 端药品查询（拍药盒 OCR 提名后触发的通用药品知识流）回复排版。保留 `KIND_TEXT`、SSE/WS 逐 token 透传与小程序通用 Markdown 气泡，不新增药品专用卡片。server-py 生成内容改为「摘要在前、安全提示在后、中间由 AI 选择 2～4 个最有价值章节」的半结构化 Markdown：摘要直接进入正文，不重复显示药品名称大标题；章节标题独占一行并与正文留出空行；章节正文可按药品特点自由选择短段落、加粗或列表。目标是稳定产生清晰的标题、换行和层级，同时避免固定四节模板造成的大段连续文字。

**Blocked by:** 无（票 51 的药品说明书流与票 52 的轻量 Markdown 渲染均已进入主线；两票剩余的支付宝开发者工具人工验收不阻塞本票施工）

**Status:** claimed

## 已确认的产品决策

- [ ] 固定首尾：开头为一段简明摘要，结尾为 `### 安全提示`
- [ ] 中间自由：AI 根据具体药品选择 2～4 个最有价值章节，不再固定为「用途/常规用法用量/常见不良反应/常见注意事项」四节
- [ ] 不显示药品名称大标题：药名已在上一条用户消息中出现，回复直接从摘要开始
- [ ] 只约束结构，不固定措辞、每节条数或正文样式；允许短段落、`**加粗**`、无序列表和有序列表
- [ ] 不支持 Markdown 表格、嵌套列表、链接或代码块；手机窄屏不适合药品表格，现有轻量解析器继续按纯文本兜底
- [ ] 免责声明不交给 AI 生成：server-py 流尾注入、server-java 出口兜底机制保持不变

## Comments

- 2026-08-07（产品决策）：对比同类产品后确认采用「固定首尾、正文自由」的半结构化回复，而非专用药品卡片或完全自由输出。固定摘要与安全提示保证稳定阅读路径，中间 2～4 个章节允许模型按药品特点选择信息重点。
- 2026-08-07（安全边界）：仅借鉴同类产品的 Markdown 组织方式，不照搬儿童按体重剂量、肾功能损害剂量调整等个体化方案。C 端继续禁止个体剂量调整、替代药推荐和个人适用性判断，免责声明仍由双端确定性注入。
- 2026-08-07（技术判断）：票 52 已证明小程序标题、加粗、列表与换行渲染链路可用；当前药品回复连成大段的直接原因是票 51 prompt 仍要求连续的 `【用途】【常规用法用量】...` 固定四节。本票优先修正生成格式契约，不扩展 Markdown 解析器。
