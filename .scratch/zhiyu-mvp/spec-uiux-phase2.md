# C 端 UI/UX 二期规格（Spec 0002）

Status: done
日期： 2026-08-09 · 来源：grilling 会话（2026-08-08/09）决议 · 对应票：67（C 端 UI/UX 二期）

## Problem Statement

C 端小程序功能已完整（23 页、tabBar 三 tab），但"门面"质量与功能不匹配。票 66 解决了基线美观问题（token/图标/空态/骨架屏/微交互）后，仍暴露四类可用性缺陷：

1. **首屏信息架构错位**：首页 AI 挂号助手主卡内嵌 3 家医院列表占去半屏，把唯一有时效、需立即行动的"待办事项"（即将就诊挂号单/待支付药品订单）压到折叠线以下；chat 空态同款主卡堆叠过长。
2. **动效缺失记忆点**：演示 9 拍占 4 拍的 chat 主舞台无入场反馈，首页打开无产品感，等待页只有裸 spinner。
3. **chat 输入区冗余占位**：消息流与输入框之间挤着两条全宽横条——常驻免责声明细条（每条 AI 消息已各自带标注，横条是冗余的"双保险之二"）与语音输入提示条（录音中/识别中/失败三态共用全宽样式，且存在状态未清除的卡死 bug，非语音场景也挂在屏上）。
4. **部分页面信息层级混乱**：profile 全场最素；挂号三级列表同构雷同、用户不知身处第几步；messages 服药打卡（到点时效信息）与普通消息混排、无已读区分；drug-orders 纯文字堆叠；report 上传无主次、detail 指标卡拥挤；appointments 待支付不突出；health 页过长堆叠；科室双栏选中感弱。

评审场景下用户明确"小程序功能全都需要演示"——每一页都是评委可见面，不存在"评委看不到"的豁免区。

## Solution

在票 66 视觉基线之上，以**一票四段、按序施工、尾部可砍**完成 C 端 UI/UX 二期。纯前端（axml/acss + 组件 props），不动业务逻辑、接口、schema 与 contracts：

1. **首页信息架构重排**：待办置顶（问候头之下、主卡之上，无待办不渲染）；registration-card 主卡瘦身——医院列表改为可选渲染，主卡只留标题与科室挂号/智能导诊双入口，医院目录折为一行轻入口跳找医院链路，校正位置随之迁移；chat 空态同源精简。功能宫格不动（"功能目录"词条：宫格与 Agent 卡片入口并存是领域决策）。
2. **chat 记忆点动画与输入区净化**：气泡与业务卡入场动画（≤400ms、transform/opacity only、`zy-` 前缀）；常驻免责横条移除（每消息/每卡片自带标注保留，preconsult 同步）；语音提示条内联进输入行（话筒按钮录音脉冲 + 输入框内识别/失败文案），并修复状态卡死。流式光标与工具进度条归票 70，本票不碰。
3. **弱页翻新**：profile 重构；挂号三级列表加步骤进度指示与卡片差异化；messages 已读区分、drug-orders 状态结构化；consult/waiting 倒计时心跳。
4. **功能页信息分层**：messages 服药打卡置顶分区；report 拍照主 CTA；report/detail 指标卡分组；appointments 待支付强化（可选前端筛选 tabs）；health 信息分层；科室双栏选中竖条。

贯穿原则：首屏自答（用户来这页干什么不滑屏可见）；时效压过目录（待办/待支付/到点提醒 > 浏览列表）；一个能力一处主入口；低频目录下沉；瞬态反馈不常驻占屏。

## User Stories

1. 作为患者，我想打开首页第一眼看到"需要我马上处理的事"（即将就诊/待支付），以便不会错过就诊时间和付款。
2. 作为患者，我想首页挂号主卡紧凑只留两个大入口，以便一屏之内同时看到待办与全部功能入口。
3. 作为患者，我想通过主卡上的一行轻入口进入医院目录，以便需要时仍能浏览附近医院。
4. 作为患者，我想在医院列表页重新校正就医位置，以便换城市时仍能正确筛选。
5. 作为患者，我想未建档/无待办时首页不出现空洞区块，以便界面始终紧凑。
6. 作为患者，我想 AI 回复气泡与医生卡/号源卡轻柔浮入，以便对话过程有生命力而不死板。
7. 作为患者，我想流式输出过程不被动画干扰、红线卡和免责声明永远即时可见，以便安全信息不被延迟或遮挡。
8. 作为患者，我想打开首页时主卡与宫格有一次性入场动效，以便感受到产品完成度。
9. 作为患者，我想等待医生接诊时倒计时有心跳感，以便确认系统仍在为我工作。
10. 作为患者，我想消息流与输入框之间没有常驻横条，以便对话内容获得最大阅读空间。
11. 作为患者，我想每条 AI 产出（回复/卡片/解读）自带免责声明，以便合规提示始终和内容在一起而不是依赖一条全局横幅。
12. 作为患者，我想语音输入的录音/识别/失败状态在输入行内联反馈，以便不挤压对话区、不错过状态变化。
13. 作为患者，我不想在非语音场景看到"识别中"挂着不走，以便界面状态永远可信。
14. 作为患者，我想"我的"页有像样的头部与真实图标，以便信任这是一个正式产品。
15. 作为患者，我想在医院→院区→科室三级选择时看到步骤进度指示，以便知道自己身处第几步、还剩几步。
16. 作为患者，我想三级列表各页卡片突出各自关键信息（医院看等级距离、院区看地址、科室看科类楼层），以便快速扫读做选择。
17. 作为患者，我想消息页区分已读未读，以便快速找到新通知。
18. 作为患者，我想到点服药提醒固定在消息页顶部，以便不会被普通通知淹没而漏服。
19. 作为患者，我想药品订单一眼看清状态（待支付/已支付/已完成/已取消），以便知道下一步该做什么。
20. 作为患者，我想报告上传页"拍照"是最突出的按钮，以便凭直觉选对最常用的入口。
21. 作为患者，我想报告详情每项指标先看结论（值/参考/状态）再看解释，以便高密度页面不费力。
22. 作为患者，我想指标操作（确认/纠错/排除）聚合在卡片底部，以便不误触。
23. 作为患者，我想待支付的挂号单在列表里最醒目，以便及时完成支付。
24. 作为患者，我想按状态筛选挂号记录，以便挂号单变多后仍能找到目标单。
25. 作为患者，我想健康档案页先看到血型/过敏等关键信息，以便紧急时一眼可得。
26. 作为患者，我想科室双栏左栏选中有明显指示，以便确认当前浏览的是哪个科类。
27. 作为评委，我想演示任意页面都有统一的精致度与信息层级，以便感知产品的完成度而非半成品感。
28. 作为演示者，我想每段 UI 改动独立 commit、尾部段落可整段放弃，以便评审前时间紧张时安全裁剪。

## Implementation Decisions

- **方向冻结**：保留票 42/66 的医疗绿方向（`#00a870` + 薄荷渐变 + 白卡）与全部设计 token，本 spec 不新增 token 值，只消费票 66 已交付的（阴影/圆角分级/语义色/动效时长/字阶/iconfont/zy-empty）。
- **一票四段、commit 级回退**：四段按序施工（首页 IA → chat → 弱页 → 信息分层），每段独立 commit；放弃整票回退颗粒度，以 commit 颗粒度替代（原 67 独立的动机——流式光标与工具进度——已由票 70 接管，剩余入场动画爆炸半径小）。
- **尾部可砍**：时间不够从第 4 段起往尾部砍，未施工段在票单 Comments 注明口径后票仍可置 done（票 27 先例）；第 3/4 段内部各条目亦按演示价值排序。
- **registration-card 双模式**：医院列表改可选渲染（props 或 slot），home 与 chat 空态统一精简模式；全量模式若无消费方则删除，不留死代码。「重新校正位置」迁移由找医院链路（hospitals 页既有定位流程）承接，不新增定位交互。
- **待办置顶**：仅调整渲染顺序，待办数据来源与"无待办不渲染"逻辑保持现状。
- **常驻免责横条移除（用户拍板 2026-08-09）**：chat 底部常驻细条（原注释"双保险之二"）删除，preconsult 同款处理。**硬约束 1 语义不变**：免责声明载体是每条 AI 消息/卡片上的 ai-disclaimer（server-py 生成注入 + server-java 出口兜底链路不动），"界面无例外"按"凡 AI 产出必自带标注"解释并持续满足；引导卡等纯客户端 UI 本就不带标注（票 62 先例），不受影响。AGENTS.md 与 CONTEXT.md 词条无需修改。
- **语音提示条内联化**：voiceHint 全宽横条退役；录音中表现为话筒按钮脉冲，识别中/失败文案显示在输入框内部（占位文案或框内弱色行），瞬态不进 messages；同步排查修复语音状态未清除导致的卡死（非语音场景横条残留）。票 70 原约定"toolProgress CSS 类留给 voiceHint 复用"由本方案取代，票 70 施工时无需保留该类。
- **气泡栏滚动条隐藏**：功能入口气泡栏由普通 view + `overflow-x: auto` 改为 scroll-view + `show-scrollbar="{{false}}"`（对齐首页待办横卡、排期日期条的既有先例），消除模拟器/部分机型的底部横向滚动条；chips 横滑能力保留。
- **页内次级 header（对话记录入口安家）**：chat 页顶部加页内 header（文档流元素），左侧当前会话标题（新对话显示「智能导诊」），右侧历史图标 +「＋」新对话一级入口；原绝对定位悬浮 ≡ 按钮退役。"对话记录"保持客户端抽屉形态不变（票 27 决策 9 自绘路线不动），仅入口归位；空态"我的挂号"悬浮链接本 spec 不动，header 图标位是其未来候选位置。
- **动画约束**：时长 ≤400ms；只用 transform/opacity；类名与 `@keyframes` 统一 `zy-` 前缀；动画只挂消息/卡片挂载时刻，不触碰 SSE token 追加路径；红线卡、免责声明标注、工具进度反馈即时可见，零延迟零遮挡。
- **与票 70 的边界**：流式光标退役、工具进度迁入气泡、思维链展示均归票 70；本票只做消息/卡片**挂载时刻**的入场效果。
- **进度指示轻量化**：挂号三级列表的步骤指示复用 consult-progress 的视觉语言但不引入问诊五步语义，仅"医院/院区/科室"三段。
- **筛选 tabs 不改接口**：appointments 状态筛选为纯前端过滤，不新增 API。
- **硬约束遵守**：免责声明标注（"仅供参考，不替代医生诊断"）在所有改动页面保持随产出标注；动效不得延迟或遮挡红线卡与免责标注。
- **领域语言**：功能宫格保持"功能目录"词条语义不变；医院目录承接"找医院"（低频主动进入）语义；首页待办不改变"挂号单/药品订单"任何状态机；语音输入保持"录制/识别/回填"词条语义，只是状态呈现位置移动。

## Testing Decisions

- **验收 seam**：C 端无自动化测试（AGENTS.md 约定），唯一 seam 是支付宝开发者工具人工走查——与票 66 同一先例。好测试的定义：以用户可见行为为准（首屏三态、动画时机、信息层级、状态条时机），不锚定实现细节（类名/结构）。
- **走查清单**：23 页无控制台错误；首页三态（有待办/无待办/未建档）首屏布局；chat 流式输出全程（含长回复与工具调用穿插）无卡顿掉帧；红线卡与每条 AI 产出免责声明即时可见且无常驻横条；语音三态（录音/识别/失败）输入行内联呈现、结束后无残留；三级列表进度指示随页面切换正确。
- **每段独立实测**：每段 commit 前完成该段走查，避免四段混测无法定位回归源。
- **自动化层**：不动 server-java / server-py / contracts，无需新增自动化测试；回归只需确认未触碰文件零变更（纯前端票）。

## Out of Scope

- 业务逻辑、接口、schema、contracts 的任何变更；B 端 admin；server-java / server-py。
- 免责声明的注入与兜底链路（server-py/server-java 侧）——本 spec 只动 C 端呈现形式。
- chat 等待态重构、思维链展示（票 70）；叫号通知与挂号凭证（票 71）；演示剧本扩拍（票 69）。
- 视觉方向重塑（深色/玻璃拟态/换主色）；复杂插画与图片资产引入。
- 弹性/果冻动效、自定义页面转场、mascot 角色动画（医疗气质不符，grilling 决议明确不做）。
- `antd-mini` 依赖与 `@vant/weapp` 构建产物的闲置清理（项目卫生问题，另行出票）。
