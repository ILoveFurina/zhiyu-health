# 号源模型：池计数，不建逐号实体

Status: accepted

号源用池计数实现：`schedules` 表携带 `total_slots` / `remaining_slots`，患者不选具体号码（真实医院挂号亦不选号）。挂号扣减 = Redis 原子 DECR + PostgreSQL 事务对账写挂号单，挂号单上记录分配序号。

被否决的方案：逐号实体（每个号一行、患者选号）——多一张表与大量边界情况，demo 零收益。

此实现同时是创新方向 D（高并发架构）唯一真实落地的点："Redis 原子扣减 + 事务对账防超卖"，其余 D 内容（异地多活、隐私计算）仅作设计文档叙述。
