# 演示武器包边界：/api/b/demo/** 收口与三重保护

Status: accepted（票 25 演示武器包）

票 25 的演示武器包（看板/重置/并发脚本/对比开关）是 demo 评审专用支撑能力，非医疗业务实体。生产环境绝不该有一键清业务数据的能力，因此必须把演示能力与业务能力物理隔离，并用保护机制让其在非演示环境"形同虚设"。

决策：演示三件套（看板、重置、对比开关写出口）的 HTTP 入口全部收口在 `/api/b/demo/**` 前缀下，与业务 B 端 CRUD（`/api/b/**`）分离；由 `AdminInterceptor` 强制 admin 鉴权。重置接口额外三重保护，三者**同时满足**才执行：

1. **环境开关** `DEMO_RESET_ENABLED`（env 注入，默认 `false`；未设置或 `false` 一律拒绝，不进入业务逻辑）；
2. **确认短语**（请求体携带固定串，防误触）；
3. **单实例互斥锁**（server-java 进程内 `AtomicBoolean` CAS，与本地单实例拓扑匹配；重置进行中再次调用直接拒绝）。

并发抢号脚本是外部脚本（`scripts/` 下），只对正常业务入口 `POST /api/c/appointments` 发 N 个并发 HTTP 请求，不新增 server-java 代码--它演示的就是真实业务路径的防超卖能力，"混合"在此是正确的。

## 被否决的方案

- **Redis 分布式锁替代进程内标志**：能防多实例，但运行拓扑是本地单实例 server-java、无注册中心、无多副本（AGENTS.md 硬约束），分布式锁是净成本，还引入重置期间对 Redis 连接的依赖。进程内 `AtomicBoolean` 完全匹配"单实例互斥锁"语义，服务器重启锁丢失可接受。
- **Spring Profile 区分 demo/prod**：项目无任何 `@Profile`/`@ActiveProfiles` 基础设施，env 变量是既有唯一机制（`.env` -> `application.yml` `${VAR:default}`）。为 demo 单独引入 Profile 机制是过度工程。
- **演示接口混在 `/api/b/**` 靠鉴权保护**（无独立前缀）：少一个前缀，但演示清数据接口与业务 CRUD 混在同一命名空间，边界不可见，未来读者无法从路径一眼区分"这是 demo 工具还是业务能力"。

## Consequences

- `/api/b/demo/**` 成为演示能力的唯一入口前缀；未来任何"演示专用、非业务"的端点都应进此命名空间，不混入业务路径。
- env 开关默认 `false` 意味着任何环境首次部署该接口即拒绝请求；只有显式在 `.env` 设置 `DEMO_RESET_ENABLED=true` 才可用，生产环境不设置即天然关闭。
- 重置失败时保持冻结、返回"已完成步骤/失败步骤/待执行步骤"清单，接口幂等可从失败步重跑，不做自动回滚（回滚本身也要清表，对 demo 无意义；重置目标本就是回到 seed）。
