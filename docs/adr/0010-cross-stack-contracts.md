# 跨栈契约：contracts/ JSON 单一事实源 + 双栈启动加载

Status: accepted

server-java 与 server-py 共享一批常量（免责声明文案、SSE 事件协议、vision 错误码与文案、上传限制、对话默认值）。历史上这些值双端各自硬编码，发生过两类 drift 事故：vision 用户可见文案两端不一致（同一场景 C 端看到不同措辞）；免责声明"仅供参考，不替代医生诊断"一度存在 3 处独立定义，改一处漏两处，直接触碰硬约束 1。

决策：仓库根 `contracts/` 下的 JSON 文件是唯一事实源（单一写点），双栈只读消费。

- server-java `config/Contracts.java`：Spring 启动期 fail-fast 加载为不可变 record，契约缺失或损坏即阻断启动（部署错误不应带病运行）；路径可用 `CONTRACTS_DIR` 系统属性/环境变量覆盖。
- server-py `app/core/contracts.py`：pydantic 模型懒加载 + 进程内缓存，首次访问失败即抛，不静默降级。
- 双栈契约一致性测试对照 JSON 与两端模型字段，防"改了 JSON 忘了模型"。

被否决的方案：

- 代码生成（JSON → 双端常量类）：多一条生成工具链与"生成物是否入库"的争论；入库产生第二事实源，不入库则离线构建断裂。demo 规模下双端各一个加载器已足够，生成步骤是净成本。
- 纯契约测试（值仍双端各写，只靠测试比对）：测试只能发现 drift、不能防止 drift——只要写点不止一个，事故必然复发。本机制把写点收敛为一，测试退居防线。

配套防复发：新常量一律先入 `contracts/` 再双端消费，禁止端内私写；该约定已写入 AGENTS.md。
