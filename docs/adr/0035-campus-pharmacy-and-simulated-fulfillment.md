# 药品履约采用一院区一药房与全局药师模拟闭环

Status: accepted

ADR-0026 将药品履约定义为平台自营中心药房，无法表达当前多医院、多院区演示中的处方归属、独立库存、价格差异和院区自取。题目同时要求药店推荐、购药配送与用药提醒，但当前阶段没有真实医院 HIS、零售药店网络、支付或物流接口。

决策：每个院区恰好拥有一个院区药房，院区与药房同事务创建，药房不能独立新增或删除。平台不设医院中心药房、平台中心药房，也不接入外部零售药店。所有院区药房同时经营处方药与 OTC，并支持院区自取和配送到家。

标准药品是全平台目录，只承载名称、规格和处方属性；院区药房通过独立关系维护价格、库存和在售状态。医生只能开所属院区药房已配置且在售的标准药品，但不以瞬时库存阻止开方。处方固化开方院区，处方药订单只能由该院区药房整单履约；OTC 订单由患者在当前服务城市内选择能够整单满足需求的院区药房。两类订单都不拆单、不跨院区调货，也不由 Agent 默认选择药房。

下单实时校验价格、在售状态和库存，并原子预扣库存；待支付订单 10 分钟后惰性过期，主动取消或过期均回补库存。处方只允许存在一张未取消、未过期的订单，支付时一次性核销，支付后的履约失败不恢复处方购药资格。订单固化履约药房、成交价、配送费、预计时效、取药地址或收货信息等必要快照。

配送和自取采用两条前向状态机，由一个不绑定院区的全局药师账号在 B 端人工推进，admin 保留相同模块权限作为演示兜底。每次推进使用条件更新，并在同一事务追加不可变履约事件和时间戳；配送生成虚构承运方与物流单号，不模拟真实骑手位置。处方用药提醒只在配送已送达或自取已取药后幂等生成，OTC 不自动生成提醒。

被否决的方案：

- 医院中心药房：仍需处理跨院区库存和自取归属，反而模糊处方来源院区。
- 平台自营中心药房：模型简单，但无法支持多院区独立价格、库存和现场补货演示。
- 外部零售药店/处方流转平台：需要药店准入、处方流转、双重审方、库存同步、结算和真实配送集成，超出当前 demo 边界。
- 每院区多个药房：增加药房准入与院区内选择问题，对当前闭环没有必要。
- 定时自动履约：掩盖角色和状态机边界，不利于演示与事务验证。

后果：`medications` 不再承载全局价格和库存；需要新增院区药房、药房药品、履约事件及订单快照，处方和处方模板明细补充配药数量。B 端药品管理改为院区药房库存管理，原 Mock 外部药店同步退出。C 端对话卡片只保留稳定、非敏感摘要并跳转统一购药确认页；敏感收货信息只进入订单快照。该决策 supersedes ADR-0026。
