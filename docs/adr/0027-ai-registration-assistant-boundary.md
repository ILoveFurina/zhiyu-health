# AI 挂号助手：AI 只确定标准科室，号源与挂号保持确定性

Status: accepted

AI 挂号助手同时支持自助挂号与智能导诊，但两条路径共享同一套 PostgreSQL 医院、院区、科室、医生、排班和挂号数据。Agent 只在智能导诊中通过多轮对话确定平台标准科室，再调用 server-java 的只读号源能力生成科室号源卡；城市筛选、距离、医生、余号和挂号均由 server-java 确定性处理，找医院不经过 Agent。

## Consequences

- C 端区分“AI挂号助手主卡片”和“科室号源卡”：前者选择科室挂号或智能导诊，后者展示当前服务城市未来 14 天的跨医院医生与号源。
- 服务城市来自用户确认的就医位置与 B 端院区数据，不在前端或 Agent 中写死；城市是硬筛选边界，不跨城市用远距离医院兜底。
- 平台维护“科类 → 标准科室”的城市标准科室目录；医院自由维护院内科室，并把实际科室映射到标准科室。
- 演示 seed 与 B 端管理共用正式业务表，不建立 Agent 或演示专用副本；关联数据由非空外键与限制删除保护，禁止级联删除。
- 科室明确后始终返回同一种科室号源卡：有号医生优先，无号医生仍展示并禁用预约；红线症状继续优先中断普通挂号流程。
