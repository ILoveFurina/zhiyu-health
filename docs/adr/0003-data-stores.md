# 数据存储：PostgreSQL + pgvector + Redis

Status: accepted

业务数据用 PostgreSQL 16（替代最初默认的 MySQL——向量扩展生态是决定性因素），向量存储用 **pgvector 扩展**（方案 1）：向量与业务数据同库，HNSW 索引，组件最少；demo 数据量（数百条知识块）下性能与专用库无差别。Redis 7 承担号源原子扣减（防超卖）与缓存。全部依赖以 Docker Compose 部署于云服务器，一键起停；团队成员通过数据库账号密码直连，云安全组仅放行团队固定公网 IP，禁止向 `0.0.0.0/0` 开放数据库端口。

被否决的方案：独立向量数据库 Qdrant / Milvus（"专用向量库"叙事更正，但多一个组件与联调面，demo 规模下无收益）。

曾考虑过 Chroma：它是嵌入式持久化向量库（非纯内存），功能足够，但不符合"独立部署数据库"的架构目标，弃用。
