# 在线问诊医生分配模式调研：自动匹配还是患者选择

- 日期：2026-08-07
- 状态：调研结论，尚未形成 ADR 或实现约束
- 调研范围：中国主流综合互联网医疗平台及医院自建互联网医院
- 证据标准：仅采用产品官网、官方帮助、官方医生端规范、医院或卫生主管部门发布的使用指南

## 一句话结论

市面主流做法不是在全产品范围内只选一种模式，而是按用户诉求设置双通道：**极速、常见问题、用户不知道找谁时自动匹配；复诊、专家咨询、用户已有明确目标时手动选择医生**。

对于智愈当前已确认的“AI 预问诊 → 患者确认摘要 → 等待医生接诊 → 医生问诊中 → 问诊已完成”主流程，两周 demo 应采用**摘要确认后自动匹配到建议科室的待接诊池，由 B 端医生明确点击接受**。这比直接把订单硬分配给某一位医生更符合“医生显式接诊”的约束，也不需要把医生选择混入摘要页。

## 官方产品证据

| 产品 | 自动匹配/非定向通道 | 手动选择/定向通道 | 可确认的场景差异 |
| --- | --- | --- | --- |
| 京东健康 | “极速问诊”属于非定向订单，由医生在派单区或抢单区接诊；页面称“智能匹配 · 秒级接诊” | “定向问诊”是患者向具体医生下单，由该医生在待接诊区接诊 | 同一产品同时支持两种模式；极速通道优化响应速度，定向通道保留医生选择权 |
| 春雨医生 | “三甲问诊”匹配公立医院在职医生；全科视频问诊强调 7×24 小时和平均 30 秒接诊 | “名医问诊”明确写明患者可自主选择专家；定向视频问诊从“找医生”筛选具体医生 | 普通、即时问题走匹配；对专家身份有要求时走自主选择 |
| 微医 | 首页提供“快速问诊”，承诺 3 分钟内医生接诊；官方帮助将其作为单独入口 | “专家问诊”由用户选择适合的专家；购买具体医生的视频问诊后按该医生队列等待 | 快速响应和专家服务被明确拆成两种入口 |
| 重医附一院互联网医院 | 未展示非定向匹配通道 | 官方流程为“选择医生 → 选择问诊服务 → 病情描述 → 支付 → 医生接诊” | 医院复诊型在线问诊强调既有科室/医生和诊疗连续性，先选医生再描述病情 |
| 首都儿科研究所互联网医院 | 未展示非定向匹配通道 | 专家咨询需先按科室查找专家，再描述病情并等待医生接诊；远程复诊也要求选择科室、医生和时间 | 专家咨询、复诊和预约型服务适合患者主动选择医生 |

### 1. 京东健康：同一平台明确区分极速与定向订单

京东健康官方《京东互联网医院问诊服务规范》将订单直接分为两类：极速问诊是医生在“派单区或抢单区”接诊的非定向服务，定向问诊是患者向具体医生下单、医生在“待接诊”中处理的服务。该规范还要求医生在接诊前查阅病历，超出执业范围时转诊。[京东互联网医院问诊服务规范](https://cont.jd.com/content/781571)

同一官方页面把快速入口描述为“智能匹配 · 秒级接诊”；京东的极速订单规则进一步说明极速电话使用“抢单制”和“抢单专区”。[京东极速问诊订单结算规则](https://cont.jd.com/content/11587472)

这说明自动模式更准确的产品表达是“非定向匹配/派单池”，并不意味着系统必须在提交瞬间把订单不可更改地绑定给某一位医生。

### 2. 春雨医生：即时服务匹配医生，名医服务自主选择

春雨医生官方开放平台将“三甲问诊”描述为匹配公立医院在职医生，将“名医问诊”明确描述为自主选择专家；同页的全科视频问诊强调 7×24 小时和平均 30 秒接诊。[春雨医生开放平台](https://m.chunyuyisheng.com/cooperation/open_api/index/)

其定向视频问诊的官方介绍则给出“找医生 → 筛选服务类型 → 选择视频问诊”的路径，并明确“定向”是为了让用户精准选择心仪医生。[春雨医生定向视频问诊介绍](https://www.chunyuyisheng.com/pc/article/197215/)

### 3. 微医：快速问诊与专家问诊分成不同入口

微医官网把“快速问诊（3 分钟内医生接诊）”与“专家问诊（专家实时在线服务）”并列展示。[微医问诊首页](https://wy.guahao.com/)

官方帮助说明，用户可在在线问诊中选择适合自己的专家；另一流程说明让用户先选择“极速问诊/专家问诊”，提交病情后等待医生接诊。[微医在线问诊帮助](https://www.guahao.com/help/docx?id=128&parentId=127)、[微医 APP 问诊流程](https://www.guahao.com/help/docx?id=16&parentId=7)

因此，微医同样不是全平台只采用自动或手动一种方式，而是用服务入口表达用户更在意“速度”还是“专家身份”。

### 4. 医院互联网医院：复诊与专家服务通常先选医生

重医附一院官方用户指南的顺序是“选择医生 → 选择问诊服务 → 病情描述 → 支付诊察费 → 医生接诊”，并注明仅支持复诊患者。[重医附一院互联网医院用户指南](https://www.fahcqmu.cn/gw_hzfw_xszl1_yhzn)

首都儿科研究所的专家咨询要求患者先通过科室过滤查找专家，再描述病情、上传资料并等待该医生接诊；远程复诊则要求选择科室、医生和就诊时间。[北京市卫健委转发的首儿所互联网医院指南](https://wjw.beijing.gov.cn/xwzx_20031/jcdt/202203/t20220317_2632811.html)

这些路径服务于复诊、明确专家诉求或预约时段。值得注意的是，它们通常**先选择医生，再填写病情**；这与智愈当前“先让 AI 完成预问诊和摘要确认”的入口心智不同。

## 两种模式分别适合什么场景

### 自动匹配更适合

- 用户只有症状，不知道应该选哪个科室或医生；
- 常见问题、首次咨询或轻问诊，核心诉求是尽快接入真人医生；
- 平台希望均衡医生工作量，并允许超范围订单转诊；
- 产品入口承诺的是“快速接诊”，而不是某位专家本人。

主要风险是用户不知道最终由谁接诊，可能对医生资历、等待时间或信任感产生疑问。因此等待页必须说明“正在匹配哪个科室的在线医生”，接诊后立即展示医生身份；不能在医生尚未接受时伪装成已经匹配成功。

### 手动选择更适合

- 复诊、慢病随访、术后咨询，患者已经认识原医生；
- 用户明确需要某家医院、某个专家或特定专科能力；
- 视频、电话等预约型服务，需要围绕具体医生的时间排队；
- 医生品牌、资历和价格本身是用户购买决策的一部分。

主要代价是流程更长，并需要真实维护医生服务状态、排班、价格、接诊范围、超时和拒诊后的重选逻辑。若医生选择发生在摘要确认后，它还会在当前五步进度中形成一个未被表达的业务步骤。

## 对智愈两周 demo 的建议

### 决策：主流程采用自动匹配，但实现为“科室待接诊池”

患者确认摘要后：

1. 系统根据预问诊结果确定建议科室；
2. server-java 创建未绑定医生的在线问诊单，进入该科室待接诊池；
3. 具备对应科室与在线资格的 B 端医生可查看脱敏后的待接诊信息和完整摘要；
4. 某位医生明确点击“接受问诊”后，才原子绑定该医生并进入“医生问诊中”；
5. C 端等待期间显示“正在为你匹配合适的在线医生”，接诊后展示医生身份。

这里的“自动匹配”是**患者不必手动选人，系统负责把订单路由到合适医生集合**；最终仍由医生主动接受。它同时保留了当前已经确认的五步生命周期：

```text
AI 预问诊 → 患者确认摘要 → 等待医生接诊 → 医生问诊中 → 问诊已完成
```

### 为什么不在当前 demo 中加入手动选择

- 摘要页已经被定义为患者与 AI 继续沟通、修改并确认摘要的专用页面，加入医生列表会混合两个任务；
- 新增独立医生选择页会让现有五步进度少表达一个真实阶段；
- 手动选择只有在医生排班、在线状态、费用、服务类型、拒诊和超时都可信时才有价值，两周 demo 很容易做成静态假选择；
- 当前需求文本强调“发送给医生”和“医生在 B 端查看摘要并接诊”，更接近非定向待接诊池，而不是患者向某位专家下单。

### 后续扩展边界

未来若需要支持复诊或名医服务，应新增独立的“指定医生问诊”入口，并采用“先选医生，再预问诊/补充病情”的路径。它可以复用相同的在线问诊单和后续三个状态，但不应插入当前摘要确认页，也不应改变默认快速问诊的五步进度。

## 结论的适用限制

- 官方公开网页未必覆盖各 App 当前版本的所有交互细节；本文只把页面或规范明确写出的流程作为事实。
- “自动匹配”不等于医疗判断由 AI 完成。AI 可整理信息和建议科室，医生是否接诊、诊断与处方仍由真人医生负责。
