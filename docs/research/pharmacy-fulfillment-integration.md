# 在线问诊后的药房接入与处方履约模式调研

- 日期：2026-08-10
- 状态：调研完成，结论已落实到 ADR-0035、`CONTEXT.md` 与 Issue 88；业务代码尚未实施
- 调研范围：中国互联网医院、互联网医药平台、电子处方外流与药品配送
- 证据标准：优先采用国家监管文件、医保部门文件、医院官方流程及上市公司年报

## 一句话结论

**智愈现阶段应采用“医院药房为默认履约方，患者可院内自取或由医院委托配送”的医院型模式；不要直接接入若干零售门店做实时比价。**

如果未来确实需要“附近药店推荐”，应把它定义为独立的**电子处方外配通道**：优先对接当地医保电子处方中心、区域处方流转平台或连锁药店总部，而不是逐家门店建设私有接口。外配药店负责二次审方、真实库存、调剂、销售和配送，智愈负责患者授权、处方流转、结果回传和全程追溯。

当前 ADR-0026 的“平台自营药房”适合快速演示单库存闭环，但不是医院型产品最自然的真实业务口径。若近期不改数据模型，建议至少把展示口径调整为“签约中心药房/云药房统一履约”，不要声称平台自己经营药品；真正落地时再按医院拆分药房与库存。

## 结论为什么不是“随便接几家药店”

药店接入并不只是同步库存和创建订单。处方药网络零售至少还涉及：

- 处方来源真实性、实名购药和一次性核销，防止同一处方重复使用；
- 医疗机构药师审方，以及履约药房的处方审核、调配和用药指导；
- 药店与电子处方提供单位签约，平台核验双方资质；
- 药品经营范围、特殊管理药品禁售、处方药和 OTC 分开展示；
- 交易、处方、药学服务、销售凭证、物流和签收信息留痕；
- 运输温湿度、药品独立放置、配送方质量协议和全程追溯；
- 缺货、部分有货、不可替代、取消、退药、召回和异常配送的责任划分。

国家市场监管总局《药品网络销售监督管理办法》明确：网络向个人销售处方药必须确保处方真实可靠并实名制；药品零售企业要与电子处方提供单位签约、审方调配并标记已使用处方；药品网络销售只能由具备相应能力的上市许可持有人或药品经营企业开展，未取得零售资质不得向个人售药。配送质量与安全也由药品网络零售企业负责。[国家市场监管总局：药品网络销售监督管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_27f2fba302ab48239dfde1a5b5095156.html)

2026 年发布的《处方药网络零售合规指南》进一步强调“凭处方、严审核、可追溯、控风险”，要求真实处方、实名销售，并明确严禁 AI 替代审方。这与智愈现有“AI 只解读处方、确定性规则与药师审核不交给 Agent”的边界一致。[国家医保局转引国家药监局发布信息](https://www.nhsa.gov.cn/art/2026/5/25/art_14_20710.html)

因此，“接几个药店 API”实际会把智愈从互联网医院应用推向药品网络交易平台；后者需要额外的平台备案、商家资质持续核验、药品质量安全管理、投诉举报、异常处置和监管报送能力，远超当前 demo 的合理范围。

## 市场上主要有四种模式

| 模式 | 典型主体 | 谁持有库存、销售并履约 | 患者体验 | 适合智愈程度 |
| --- | --- | --- | --- | --- |
| 院内药房 | 医院自建互联网医院 | 医院药房 | 处方缴费后选择院内自取或配送到家 | **当前最合适** |
| 医院 + 签约云药房/医药企业 | 医院与持证医药企业合作 | 签约企业调剂并配送，医院保留诊疗与处方管理 | 线上审方、支付、配送，药品可从合作方仓库直发 | 合适的扩展形态 |
| 处方外流到零售药店 | 医保/区域处方流转平台、连锁药店 | 患者选择的定点药店 | 搜药、比价、到店取或送到家 | 后续阶段，不宜当前直做 |
| 自营 + 平台 + 即时零售混合 | 京东健康等消费医疗平台 | 自营仓/自营店及第三方商家共同供给 | 品类广、时效快、跨场景购药 | 不适合直接照搬 |

### 1. 院内药房：医院型互联网医院最自然的默认路径

济南市中心医院 2026 年公布的线上复诊购药流程是：医生在线诊疗并开立医嘱，患者在处方缴费后选择“自取”或“送药到家”。这是一条完整的医院内闭环，不需要先展示多家药店。[济南市中心医院：互联网医院线上复诊购药流程](https://qsy.jinan.gov.cn/col/col10160/art/2026/art_d0b8e995dc3f4c00a43f6fcc41b199e6.html)

国家卫健委《互联网诊疗监管细则（试行）》也没有要求互联网医院自建配送，而是允许医疗机构“自行或委托第三方”开展药品配送；无论哪种方式，协议和处方流转信息都应可追溯，并向省级监管平台开放数据接口。[国家卫健委：互联网诊疗监管细则（试行）](https://www.nhc.gov.cn/yzygj/c100068/202203/2072f0e8988249e59d942e1b2a933916.shtml)

这个模式的核心不是“医院自己送快递”，而是医院药房完成药学与调剂责任后，可以把物流委托给合规配送商。

### 2. 医院 + 云药房：把供应链交给专业持证机构

上海市儿童医院与国药、上药合作的“云药房”案例中，医院医生开方、药师在线审核，处方信息传给医药配送企业，由企业仓库调配并专业配送到患者本人；医院保留诊疗和审方链路，供应与物流交给专业机构。[上海交通大学医学院：附属儿童医院互联网医院开通云药房](https://www.shsmu.edu.cn/news/info/1005/18835.htm)

这比“平台自营药房”更适合作为智愈当前单一全局库存的真实解释：智愈本身不冒充药品零售经营者，而是连接一家具备资质的中心履约方。若将来服务多家医院，中心履约方还可以同时承接多个医院的处方，但处方来源、药师审核、订单和结算仍需清晰分账和追溯。

### 3. 处方外流：药店推荐是区域基础设施，不只是产品功能

新疆医保电子处方流转平台的官方方案已经包含开方、审方、药品比价、第三方配送和结算。患者可按价格、距离和综合评价选择定点零售药店；药店需维护药师、药品、进销存、追溯和冷链能力，并与医保平台对接。[新疆医保局：医保药品外配电子处方流转服务](https://ylbzj.xinjiang.gov.cn/ylbzj/yywfgl/202210/44da4bbe61404209a69add965b24ec7c.shtml)

国家卫健委 2023 年答复显示，全国各省级医保部门均已启动医保电子处方中心部署，截至当年 6 月已有近 20 个省份正式上线，实现定点医疗机构处方流转到定点零售药店。[国家卫健委：关于电子处方流转相关提案的答复](https://www.nhc.gov.cn/wjw/tia/202309/88138dc7b08247a8b31825b90403bad9.shtml)

这说明真实产品要做多药店推荐时，优先路径应是接入属地医保/处方流转基础设施。自己逐家药店建立私有接口，会重复建设身份、处方真实性、核销、支付与追溯机制，也更难形成统一数据质量。

湖北省互联网医院药学服务规则给出了更完整的责任链：医疗机构药师先审核处方，审核合格后可以在实体医疗机构取药、委托第三方配送，或流转到零售药店；零售药店收到处方后还要完成调配、核对和配送，并对药品供应质量承担责任。这说明“院内药房”和“外部药店”可以并列，但外部药店不是一个只接收订单的普通商户。[湖北省卫健委：互联网医院药学服务管理办法](https://wjw.hubei.gov.cn/zfxxgk/zc/gfwj/202101/t20210114_3244181.shtml)

### 4. 京东健康：混合供给建立在重供应链能力上

京东健康 2025 年年报将零售药房描述为自营、线上平台和即时零售协同的全渠道模式；截至 2025 年底运营超过 300 家自营药房，并把这些药房纳入即时零售网络。它同时强调“问诊 + 检查 + 诊断 + 药品”的闭环和供应链能力。[京东健康 2025 年年报](https://manager.wisdomir.com/files/586/2026/0424/20260424171501_75649801_en.pdf)

这类模式适合拥有药品经营资质、仓储、直营网点、招商治理和履约网络的大型平台。智愈当前是医疗 B+C demo，若只复制“附近药店列表”，却没有复制处方核验、药师、商家治理和物流质量体系，会只得到表面相似而业务责任失真的功能。

## 院内药房与外部药店的取舍

| 维度 | 院内药房/医院签约云药房 | 多家外部药店 |
| --- | --- | --- |
| 处方与药学闭环 | 医生、医院药师、处方、调剂链路清晰 | 医疗机构与药店双端协同，退方与二次审核更复杂 |
| 药品目录 | 受医院目录限制，但与诊疗一致性较强 | 覆盖更广，药品品牌、规格和替代关系更复杂 |
| 库存与时效 | 单履约方，准确性和承诺较容易管理 | 需实时或准实时同步多门店库存和配送能力 |
| 患者选择 | 选择少，流程短 | 可比较价格、距离、时效，自主性更强 |
| 医保与结算 | 与医院收费体系结合较自然 | 通常依赖当地医保电子处方中心和定点药店能力 |
| 合规与运营成本 | 相对集中 | 平台需要商家准入、持续核验、质量与投诉治理 |
| 对当前代码影响 | 中等：按医院拆库存和履约点 | 高：药店、门店库存、报价、拆单、核销、结算、配送全要新增 |

## 对智愈的推荐方案

### 阶段 0：当前 demo，保持闭环但修正业务表述

短期不扩展到真实药店网络，保留“一份目录 + 一份库存 + 确认后下单 + 模拟支付 + 履约状态”的实现。建议把产品和答辩口径从“平台自营药房”调整为：

> 智愈连接一家虚构但具备资质的签约中心药房/云药房，统一承接已审核处方的调剂与模拟配送；多药店库存同步仅用于展示未来处方外配能力，不参与真实下单。

这样无需立即修改数据库，也避免声称一个医疗软件平台自行持证售药。需要注意：这只是 demo 口径，不代表正式系统已经满足经营、药学和配送资质要求。

### 阶段 1：产品化 MVP，优先接医院药房

若目标客户是医院或互联网医院，建议落地：

1. 每家医院配置一个或多个 `fulfillment_site`，第一类站点为 `HOSPITAL_PHARMACY`；
2. 处方沿就诊来源绑定医院，医院药师审核后进入该医院药房；
3. 用户只选“院内自取”或“配送到家”，不先选药店；
4. 配送由医院药房委托物流商，物流只拿最少必要信息；
5. 缺货时明确展示“本院无货”，不允许 Agent 自行替换药品；
6. 处方解读和服药提醒继续基于医生处方，不能因履约方变化而改变用法用量。

此阶段需要把当前全局 `medications.stock` 拆为“标准药品目录”和“医院药房库存”。至少应新增医院/履约站点维度、取药方式、收货信息、药师审方记录和物流状态。

### 阶段 2：增加处方外配，但只做一个标准通道

只有在出现以下明确需求后，再做外部药店：医院目录缺药、患者异地、慢病长期用药、医保双通道药品，或产品明确需要价格/距离/时效比较。

优先级建议：

1. 属地医保电子处方中心或区域处方流转平台；
2. 全国/区域连锁药店总部的标准接口；
3. 具备合规能力的医药交易/履约聚合平台；
4. 最后才考虑单店私有接口。

这一阶段至少要新增：`pharmacy_organizations`、`pharmacy_stores`、`store_offers`/门店库存、`prescription_redemptions`、履约选择、价格快照、拆单策略、药店审方结果、核销凭证、物流轨迹、签收凭证、退款/退药和召回状态。

向外部药店传处方、向配送商传地址时还要遵守最少必要原则。医疗健康信息和行踪轨迹属于敏感个人信息；向另一处理者提供个人信息，需要告知接收方、目的、方式和范围并取得相应同意。正式接口应优先传短期处方令牌和履约所需字段，不能把完整问诊记录或病历原文直接交给药店和配送商。[全国人大：中华人民共和国个人信息保护法](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)

### 阶段 3：再做“价格 + 距离 + 时效”推荐

推荐只能发生在合格履约候选集合内，排序应由确定性规则完成，不让 LLM 决定购药渠道：

1. 先过滤资质有效、经营范围覆盖、处方可承接、全处方有货且配送范围覆盖的门店；
2. 再按患者明确选择的偏好排序，例如总价最低、距离最近或最快送达；
3. 默认优先整单履约，避免为了低价把一张处方拆到多家药店；
4. 展示价格时间戳、库存时间戳、预计送达、配送费和不能配送的药品；
5. 最终由患者确认药店，Agent 只能解释差异，不能替患者静默下单。

## 对现有 ADR-0026 的建议

ADR-0026 的工程判断——当前不做多药店——仍然正确；需要复议的是“平台自营药房”这个领域语义。建议后续单独开决策票，在以下两案中选择：

- **推荐案：医院药房模型。** 与医院型 B 端、在线问诊和处方审核最一致，但需要按医院拆库存，改动较大。
- **过渡案：签约中心药房模型。** 保留全局库存和单履约方，改动小，适合作为 demo 到产品 MVP 的过渡。

不建议继续使用“平台自营药房”作为真实产品承诺，也不建议为了补题面上的“药店推荐”立刻引入三家虚构药店参与下单。当前 Mock 库存同步可继续保留，但界面应明确标注“演示数据/未来外配能力”，避免用户误认为这些药店是真实履约方。

## 最终决策口径

面向评审或产品讨论，可以直接表述为：

> 智愈当前按互联网医院模式设计，医生开方后先由药师审核，默认由就诊医院药房履约，患者可选择院内自取或合规配送到家。未来需要院外购药时，通过医保电子处方中心或连锁药店总部接入合格药店，患者再按价格、距离和时效自主选择。Agent 只整理信息、解读处方和辅助比较，不开方、不替代药师审方，也不未经确认下单。
