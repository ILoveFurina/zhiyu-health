# 医疗助手是否需要 RAG：产品与证据调研

> 调研日期：2026-08-07  
> 范围：C 端医疗助手、症状检查器、医疗搜索与临床助手。仅使用产品官方资料、监管机构材料及同行评审原始研究。产品没有公开运行机制时，本文明确写“未披露”，不以“知识库”“知识增强”等宣传语反推其采用 RAG。

## 结论先行

**RAG 不是医疗助手的基础必选项，也不应成为导诊和挂号的默认路由。** 产品证据呈现出清晰分层：

1. 症状检查、紧急度判断和科室导诊多采用临床路径、概率推理、专用模型或受控追问；最终医院、科室、医生和号源来自确定性业务数据。
2. RAG 的明确价值集中在另一类任务：回答必须引用最新指南、药品说明书、机构政策、患者记录或其他私有资料时，为生成提供可更新、可审查的证据。
3. “接了 RAG”不等于医疗安全。检索错配、来源质量、引用与结论不一致、旧版本知识和生成模型误读证据仍需单独治理和评测。
4. 智愈当前 50 条通用症状短文本没有权威出处、版本、审核人、证据等级和原文引用，既不能形成产品壁垒，也不足以证明比 `doubao-seed-2.1-turbo` 的参数知识更安全。它适合作为技术演示数据，不适合作为 C 端默认医疗回答依据。

对智愈 MVP 的直接建议是：**C 端导诊、预问诊、挂号默认不使用 RAG；保留 RAG 基础设施作为 B 端可切换演示。只有取得可授权、可版本化、可逐条引用的权威语料后，再把 RAG 上线到限定的知识问答场景。**

## 1. 典型产品实际上怎样“接地”

### 产品证据不支持的推论

- 有“医学知识库”不等于采用 RAG；知识库也可能用于概率图模型、规则、搜索结果页或模型训练。
- 有“引用”通常说明存在某种检索/接地，但若官方未披露，不能据此断言具体采用向量 RAG。
- 使用医疗大模型不等于不需要外部知识；是否检索应由任务对时效、私有信息和可追溯性的要求决定。

## 2. RAG、裸模型、联网搜索和确定性工具的边界

| 机制 | 最适合 | 不适合 / 主要风险 |
|---|---|---|
| 裸模型 | 语言理解、改写、摘要、同理表达、基于已给上下文组织回复；低风险通用解释 | 最新指南、精确药品信息、院内政策、实时号源；无法天然给出可靠出处，知识截止时间不可控 |
| 受控文档 RAG | 授权指南、说明书、院内制度、患者教育材料、患者自己的记录；要求版本和引用的问答 | 小而粗糙的通用常识库；个体诊断；把召回文本直接当正确答案 |
| 白名单联网搜索 | 新指南、新警示、快速变化的公共信息；需要覆盖本地库之外的资料发现 | 开放网页直接生成医疗建议；来源质量、SEO、冲突证据、网页变更和提示注入难治理 |
| 确定性规则 / 业务工具 | 红线症状、禁忌校验、身份权限、医院科室目录、排班、余号、下单和审计 | 开放式解释、复杂自然语言归纳；规则覆盖不足时需明确降级和人工出口 |
| 专用概率/分类模型 | 症状实体识别、受控追问、紧急度或标准科室候选 | 不能替代实时业务查询，也不天然提供循证解释 |

RAG 原始论文提出的优势正是显式知识可更新、可检查和可提供来源，而不是“让模型更懂所有问题”；它在开放域知识任务中优于纯参数模型，但这不是医疗安全证明。[Lewis 等，NeurIPS 2020](https://proceedings.neurips.cc/paper/2020/file/6b493230205f780e1bc26945df7481e5-Paper.pdf)

### 为什么联网搜索不能简单替代受控 RAG

一项由神经科医生评审、覆盖 13 份近期指南和 130 个问题的原始研究给出了很有价值的对比：GPT-4o 裸模型正确率为 60%，限定到目标指南的文档 RAG 为 87%，在线搜索 RAG 为 67%；在线 RAG 与裸 GPT-4o 的总体差异未达到显著，而文档 RAG显著更好。在线 RAG 的真实引用率更高，但仍会给出错误或可能有害的回答；研究还发现 RAG 对知识型问题强于病例型问题，检索结果对措辞很敏感。作者建议在线系统采用权威域名白名单，并强调严格、多样化测试。[Masanneck 等，npj Digital Medicine 2025](https://www.nature.com/articles/s41746-025-01536-y)

这说明合理优先级是：

1. 能用确定性业务数据回答的，不联网搜索。
2. 需要权威证据时，优先检索经过治理的固定来源并展示原文、版本和日期。
3. 只有受控库覆盖不了且时效价值足够高时，才使用白名单联网搜索。
4. 检索失败、证据冲突或证据不足时，明确收窄回答或拒答，不把裸模型猜测包装成检索结论。

## 3. 医疗安全、可追溯、时效与评测

### RAG 能改善什么

- **时效**：知识可以在不重训模型的情况下更新。上述神经科研究中，裸模型对较新指南表现下降，而在线检索对新指南更有帮助。
- **可追溯**：用户或医生可以打开支持回答的原文；但必须再验证“引文是否真的支持该断言”。
- **私有知识**：院内流程、医院科室说明和患者自己的记录通常不存在于基础模型参数中。
- **小模型补强**：一项局部部署的放射科对比剂咨询研究中，受控 RAG 将 Llama 3.2-11B 的幻觉从 8% 降到 0%，平均排名明显提高，但放射科医生仍把更强的云模型排在它之前；结果只适用于 100 个合成场景，不能外推成普遍结论。[Wada 等，npj Digital Medicine 2025](https://www.nature.com/articles/s41746-025-01802-z)

### RAG 不能自动解决什么

- 错召、漏召、切块丢失上下文和用户俗语与指南术语不匹配。
- 来源本身过时、低质量、互相冲突或不适用于当前人群。
- 模型引用了真文献，但生成的结论没有被文献支持。
- 个体情况信息不足、病情演变和需要查体/检验的临床不确定性。
- 极端病例和重复生成的最坏情况可靠性。

WHO 对健康领域大模型的指导强调虚假、不准确、偏倚、不完整陈述和自动化偏差风险，并要求把系统限制在定义清晰、具备必要准确性与可靠性的任务上，开展发布后审计和影响评估。[WHO 2024 指南发布页](https://www.who.int/news/item/18-01-2024-who-releases-ai-ethics-and-governance-guidance-for-large-multi-modal-models)

NHS 111 即使使用受治理的临床路径并被作为医疗器械管理，也明确要求其结果不能替代临床评估，医学决定不得仅依赖系统输出。这一边界显然不会因为换成 RAG 而放宽。[NHS 111 安全信息](https://digital.nhs.uk/services/nhs-111-online/nhs-111-online-is-a-class-1-medical-device)

### 上线前至少评测这些指标

| 层级 | 建议指标 |
|---|---|
| 路由 | 导诊/知识问答/挂号/报告/药品意图混淆矩阵；“该挂什么科”误入 RAG 的比例必须为 0 |
| 红线 | 危险输入召回率、漏报率、误报率；规则引擎必须先于模型和检索 |
| 检索 | Top-k 证据召回率、无答案识别、俗语/错别字/多轮省略鲁棒性、版本与有效日期 |
| 生成 | 医生评审的正确性、安全性、完整性、不确定性表达；逐断言 citation entailment |
| 导诊 | 标准科室 Top-1/Top-3、必要追问质量、过度确定率、跨城市或不存在科室率 |
| 可靠性 | worst-of-n、重复问答一致性、检索服务失败/超时/空召回降级行为 |
| 产品 | 端到端时延、成本、用户是否看懂来源和免责声明、转人工/就医完成率 |

评测应使用真实风格但完全虚构或充分脱敏的中文多轮样例，由临床人员制定逐题标准；不能只用医学考试选择题或只测“最终答案相似度”。OpenAI 的 HealthBench 也把紧急转诊、不确定性、必要追问、沟通质量和最坏情况可靠性拆开评测，说明单一准确率不足以描述医疗助手。[HealthBench 官方说明](https://openai.com/index/healthbench/)

## 4. 智愈各 C 端场景的明确建议

### 4.1 智能导诊与挂号：不使用 RAG 作为主流程

推荐链路：

```text
server-java 红线规则
  → 专用导诊意图与标准科室解析
  → 信息不足：受控追问一个关键问题，保持在导诊状态
  → 科室收敛：调用 server-java 科室/号源工具
  → 展示当前城市的真实科室号源卡
```

- “头疼两天，该挂什么科”必须进入专用导诊编排，不能因 `ambiguous` 退回普通 Agent/RAG。
- RAG 即使未来存在，也只能作为解析器内部不可见的辅助证据，不得覆盖红线规则、标准科室目录或实时号源。
- 当前 [ADR-0027](../adr/0027-ai-registration-assistant-boundary.md) 的“AI 只确定标准科室，号源与挂号确定性处理”方向正确。

### 4.2 预问诊：默认不使用外部医学 RAG

- 目标是结构化采集主诉、现病史、既往史等用户事实并生成医生可审阅摘要，不是给出诊断或治疗知识。
- 问题路径应来自可版本化的表单/临床模板或受控状态机；模型负责理解用户表达、发现字段缺失和总结。
- 未来如果不同科室有院内预问诊模板，可检索“模板/流程配置”，但这属于私有流程接地，不是通用症状知识 RAG。

### 4.3 通用健康问答：当前关闭 RAG；若正式上线，必须重建知识治理

- 现有 50 条 seed 仅保留为技术演示，不进入默认 C 端链路，也不因空召回向用户暴露“知识库没有内容”。
- 若产品只需一般解释，可由基础模型回答并严格限制为健康信息，不做诊断、剂量和个体治疗建议，同时保留红线出口。
- 若产品承诺“循证、最新、可核验”，则 RAG **有必要**，但前提是：获得授权的指南/共识/患者教育材料，记录来源、适用人群、版本、发布日期、失效日期和审核人；答案展示逐条引用并允许查看原文。
- 白名单联网搜索可以作为受控知识库之外的补充，不应直接搜索开放网页后给用户医疗结论。

### 4.4 报告解读：首先接地用户报告，不默认检索通用库

- 报告本身就是第一证据源；保持现有独立视觉管道、结构化 Schema、工具隔离和不确定时拒绝。
- 指标定义和一般性解释可由模型完成；涉及“最新指南建议、复查周期或治疗决策”时，要么不回答，要么检索经过审核的指南并展示来源。
- 不要用通用症状 chunk 混入报告解读；它可能把非患者特异知识误当成患者结论。

### 4.5 药品知识：正式产品应优先官方说明书/监管数据接地

- 药名、适应证、禁忌、不良反应和剂型会变化，且精确性要求高；正式能力不应只依赖裸模型参数知识。
- MVP 可以维持“通用解释 + 咨询医生/药师”的严格边界，但不得宣传为完整说明书或最新用药依据。
- 后续应采用国家药监部门核准说明书、平台合法取得的药品数据库或厂家最新版说明书，优先结构化查询，长文本解释再用 RAG；显示来源和更新日期。
- C 端仍不做个性化用药决策；个性化禁忌留在 server-java 的 B 端开方确定性规则中，符合 [ADR-0028](../adr/0028-pill-box-generic-knowledge-stream.md)。

### 4.6 医院、医生、号源、订单与平台政策：只用业务工具

这类信息有唯一真实来源且持续变化，应从 server-java 的 PostgreSQL/Redis 业务能力读取。医院内部就诊指南、检查准备事项等长文本可在未来使用私有 RAG，但具体可预约对象和余号永远不能由检索文本或模型生成。

## 5. 对现有 ADR-0010 的处理建议

现有 [ADR-0010](../adr/0010-rag-knowledge-retrieval.md) 把 `triage` 默认知识源设为 RAG，并要求“导诊前先检索知识”。这与本次产品证据和 ADR-0027 的专用挂号边界已经不一致。建议另开 ADR 修订，而不是只修 embedding：

1. C 端默认 `knowledge_source=none`；B 端演示页继续允许切换 RAG/图谱。
2. `registration/triage` 和 `preconsultation` 使用各自的专用编排，不注入 `search_knowledge`。
3. 只有显式 `evidence_qa` 场景可注入检索工具，并且未来启用前必须满足语料治理与评测门槛。
4. 空召回、超时、低分召回不得向 C 端暴露内部实现；对于要求证据的问答，应输出“暂无足够可靠资料”，而不是静默把裸模型猜测伪装成循证回答。
5. 保留现有向量/图谱链路作为答辩技术能力，但演示文案应诚实标注“技术对比”，不声称 50 条 seed 能提升医疗安全。

## 最终判断

问题不应是“医疗助手要不要 RAG”，而应是“这一次回答是否需要一个模型参数之外、可验证且受治理的事实源”。

- 对“该挂什么科、有没有号、帮我挂号”：**不需要 RAG，需要受控导诊与确定性工具。**
- 对“请整理我的症状给医生”：**不需要外部 RAG，需要结构化采集和忠实总结。**
- 对“最新指南怎么说、这个药的核准说明是什么、医院检查前要准备什么”：**需要受控检索、版本和引用；这时 RAG 才有明确产品价值。**
- 对当前智愈 MVP：**RAG 应定位为可切换技术演示，而不是 C 端默认医疗能力。**
