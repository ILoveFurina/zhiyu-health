## 🎯 选题背景

随着 AI 技术的发展，传统的“挂号 + 问诊 + 买药”流程正在被重构。用户不再满足于被动操作，而是需要一个**懂医疗、能决策、会关怀**的 AI 健康伴侣。

**你的任务**：
 构建一个**B+C 深度联动**的新一代医疗平台：

- **C 端**：设计一个**医疗 AI Agent**（嵌入小程序/APP），作为用户的“第一联系人”，智能处理挂号、问诊、买药、健康管理等需求。
- **B 端**：搭建**医生/医院管理后台**，为 AI Agent 提供数据支撑和服务能力，同时赋能医生提升诊疗效率。

**核心挑战**：如何让 AI Agent 不仅是一个“问答机器人”，而是能**真正完成业务闭环**的智能助手？

## 📋 核心功能建议

### C 端：AI Agent 智能体（核心亮点）

**1. 智能导诊与挂号**

- **多轮对话理解**：用户描述“我头疼三天了，还有点发烧”，Agent 能追问细节（部位、体温、过敏史等）
- **科室推荐**：基于症状推荐最合适的科室（如：神经内科 vs 发热门诊）
- **医生匹配**：根据科室、医院等级、医生擅长、号源情况，推荐 3 位医生供选择
- **完成挂号**：Agent 调用 B 端接口，完成挂号并返回挂号凭证

**2. 在线问诊与处方**

- **预问诊整理**：Agent 先与用户沟通，整理病情摘要（主诉、现病史、过敏史），发送给医生
- **医生接诊**：医生在 B 端查看摘要，发起图文/视频问诊（可模拟）
- **电子处方**：医生开具处方后，Agent **解读处方内容**（药品名称、用法用量、禁忌），用通俗语言告诉用户

**3. 处方购药与配送**

- **药店推荐**：基于处方药品，推荐附近有货的药店（结合价格、距离、配送时效）
- **一键购药**：用户确认后，Agent 完成下单并跟踪配送状态
- **用药提醒**：购药后，Agent 自动设置用药提醒（如“每日 2 次，饭后服用”）

### B 端：医疗管理后台

**1. 医院与科室管理**

- 医院信息维护（等级、地址、简介）
- 科室设置与医生关联
- 号源池管理（每日放号量、排班规则）

**2. 医生工作台**

- **排班管理**：医生设置可接诊时段（支持批量排班）
- **接诊台**：查看 AI 整理的病情摘要，发起问诊，开具电子处方
- **病历查看**：查看患者历史就诊记录和用药史

**3. 处方与药品管理**

- 处方模板管理（常用药组合）
- 药品库存同步（与药店数据打通）
- 处方审核（药师审核处方合理性，可简化为状态标记）

## 🚀 创新挑战建议

### 方向 A：Agent 的“拟人化”与“情感化”

- **情感陪伴**：当用户焦虑时（如“我是不是得了重病”），Agent 能识别情绪并给予安抚
- **主动关怀**：问诊后 3 天，Agent 主动询问“您好些了吗？药吃完了吗？”
- **多模态交互**：支持用户上传舌苔/伤口照片，Agent 结合图像给出初步建议（需调用视觉模型）

### 方向 B：医疗知识图谱与推理能力

- **构建知识图谱**：建立“症状 - 疾病 - 科室 - 药品”的关联图谱
- **可解释推荐**：Agent 推荐医生时，能说明理由（如“这位医生擅长偏头痛，好评率 98%”）
- **禁忌检测**：医生开药时，Agent 自动检测药物相互作用或过敏风险，提醒医生

### 方向 C：复杂业务场景的自动化

- **商保快赔**：问诊结束后，Agent 自动整理理赔材料，一键提交商保报销
- **慢病管理计划**：针对糖尿病/高血压患者，Agent 生成 30 天管理计划（饮食、运动、用药、监测）
- **家庭账户**：一个账号管理全家健康，Agent 能区分“给妈妈挂号”和“给孩子买药”

### 方向 D：高并发与系统架构

- **挂号秒杀**：模拟热门专家放号场景，设计防超卖、防刷号的并发控制机制
- **异地多活**：设计跨区域的医疗数据同步方案（如上海医生查看杭州患者病历）
- **隐私计算**： patient 数据在不泄露前提下，支持 AI 模型训练和统计分析

## ⏱️ 工期

**MVP 范围（建议）**：

- C 端：完成**智能导诊 + 挂号**的单线流程（Agent 能对话、能推荐、能挂号）
- B 端：完成**医院/医生基础管理 + 排班 + 号源**功能
- 技术：可用 Mock 数据简化处方、购药等环节

## 🏆 建议重点考虑

| 维度                | 评分关键点                                            |
| ------------------- | ----------------------------------------------------- |
| **AI Agent 智能度** | 对话是否自然？能否真正完成任务？有没有情感/推理能力？ |
| **业务闭环完整性**  | 挂号→问诊→开方→买药流程是否打通？B+C 端数据是否联动？ |
| **创新性**          | 是否有业务创新性、技术创新性？                        |
| **用户体验**        | C 端交互有是否流畅？B 端医生操作是否高效？            |
| **系统架构**        | 代码质量、并发设计、扩展性、部署方案                  |

## 💡 Tips：

1. **Agent 不是 Chatbot**：不要只做问答，要让 Agent**调用 API 完成实际业务**（挂号、下单、预约）
2. **医疗无小事（重要！要有质量风险意识）**：在 Demo 中体现**合规意识**（如：标注“AI 建议仅供参考，不能替代医生诊断”）
3. **数据 Mock 要合理**：即使没有真实医院数据，也要 Mock 出合理的科室、医生、药品信息
4. **突出差异化**：其他小组里可能也做“智能导诊”，你们组的**创新点**是什么？
5. **演示胜过千言**：答辩时准备一个**3 分钟的视频 Demo**，让评委直观看到 Agent 如何与用户对话并完成闭环
