# 工程碰壁复盘

本目录供项目成员在复盘会、代码审查和阶段总结时查阅，用来记录 issue 实施过程中具有复用价值的判断失误、返工原因和验证教训。

这里不是项目规范、开发前置材料或架构决策来源。正式约束以 `AGENTS.md` 和 `docs/adr/` 为准；复盘中的建议需要经过单独讨论，才能升级为规则或 ADR。

## 收录标准

以下情况适合记录：

- 架构或目录归属发生实质返工；
- 安全、权限、隐私或一致性边界在后期才被发现；
- 实现能够运行，但不满足确定性、幂等性或失败语义；
- 验证命令产生假阳性、假阴性或大量误导噪音；
- 同一问题经过多轮审查才收敛。

普通拼写修复、一次性环境波动和没有复用价值的施工细节不记录。

## 编写原则

- 记录关键判断和推翻它的证据，不粘贴完整施工日志或聊天记录。
- 区分实现缺陷、规则歧义、工具误用和环境噪音。
- 不记录患者敏感原文、真实凭据或可识别个人的信息。
- 使用 [`TEMPLATE.md`](TEMPLATE.md) 保持结构统一。
